# Start a repository with the current SSOT process

Use [the canonical process](docs/SSOT_PROCESS.md) and the five files in
[`docs/ssot-starter/`](docs/ssot-starter/). This source instruction pack is the
current new-repository path. The packaged `yakherd setup` and `Start Yakherd`
launcher still install/use the legacy five-role process; do not run them as a
step in these instructions. The process broker can be retained independently.

Give your agent the target repository and the actual product request together
with this instruction:

> Adopt the current Yakherd SSOT process from `docs/SSOT_PROCESS.md` in the
> Yakherd source checkout. Inspect the target first. For a new repository, use
> `docs/ssot-starter/` to create AGENTS.md, SSOT.md, BASELINE.md, NOW.md and
> README.md without overwriting existing work. Adapt the mission and first
> milestone from my request; mark unknown facts honestly. For an existing
> repository, use `docs/SSOT_MIGRATION.md` and preserve its evidence and real
> technical constraints. One implementation task is the default. No mandatory
> role roster, bootstrap Red Team gate, review ledger or separate approval of
> a restated request. Preserve independent verification where the product or
> claim needs it. Check that the repository alone explains what to do next,
> then carry out the authorized next action. Do not publish or push unless I
> have authorized it.

Include an absolute path or accessible repository reference to this checkout
when using that prompt elsewhere. If the source is unavailable, obtain these
files before adopting the process; do not substitute the old installed shell.

Adapt all `{{...}}` placeholders. In `NOW.md`, put the real goal, allowed and
forbidden scope, observable completion checks and next command/action. Do not
invent a product when none has been supplied. The target files must be
self-contained: no required read from another project's checkout on resume.

For a genuinely new repo, create only absent paths. A collision triggers
inspection and the migration procedure for the affected path, not an
overwrite or a wholesale reinstall. No package installation, Git creation,
network access, background team, or empty paperwork directory is needed just
to establish these owners.

Check that local links resolve, placeholders are gone, there is one current
objective, and no old launcher remains active. Test the product only to the
extent required by its actual changes. Report the files created or adapted,
what is proven, and the next executable action.
