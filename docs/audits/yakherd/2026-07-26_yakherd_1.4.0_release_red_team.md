## Blocking finding

### P1-1: additive fresh setup misses final-component case-fold collisions on case-sensitive filesystems

Accepted Requirement 4 requires every payload-path case alias to fail before
mutation, and the implementation section retains complete collision and case
checks. `safe_destination()` validates the destination's parent, but validates
the final destination component only inside `if lexists(destination)`
(`bootstrap.py:74-101`). `preflight_fresh()` then treats a destination as
colliding only when that exact spelling exists (`bootstrap.py:244-261`).

On a case-sensitive filesystem, an existing `readme.md` does not make
`lexists(target / "README.md")` true. The final component therefore never goes
through the helper's case-fold enumeration, preflight reports no collision,
and `write_fresh()` can create `README.md` beside it. The same defect applies
to any differently cased payload filename or install receipt. This path is new
and reachable specifically because 1.4.0 permits fresh installation into a
nonempty target. It creates a repository that is ambiguous or uncheckoutable
when moved to a case-insensitive filesystem and contradicts the exact
fail-closed case-alias contract.

The existing tests cover an exact `README.md` collision and target-root casing,
but not a differently cased final payload component. The correction must make
the final component participate in exact-case/case-fold validation even when
the requested spelling is absent, and add an adversarial additive-install test
that passes on both case-sensitive and case-insensitive platforms. No retrofit
policy or other scope needs to change.
